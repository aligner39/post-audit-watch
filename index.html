Post-Audit Watch

It works on public data. I need no keys, no repo access and no write access.

  • Audit text matching: looks for a finding's quoted line in deployed source. It is a text match, and I have not measured its precision.

I'd build this in your pilot

  • One new watcher, chosen with you: queued governance actions, oracle and key-parameter changes, or a reviewed baseline that answers "was this ever reviewed?"

Three roles check each other. A proposer emits structured hypotheses, a skeptic attacks them, and a validator checks required fields before anything is trusted. A truncated model response loses only its broken part, because complete JSON objects are salvaged. Today these roles review code hypotheses. They do not yet review control-plane changes.

It can't quietly overspend

1. ReserveMoney is booked under a file lock before the paid call goes out.
2. CallIf the worker dies here, the money stays committed.
3. SettleThe actual cost replaces the reservation. Abandoned reservations get charged, never released.

Per-path and global daily ceilings are enforced atomically, so concurrent workers can't race past a limit.

If a dependency fails, the system stops instead of guessing. One recent fix: an Etherscan rate limit was making verified contracts look unverified, so that path now fails closed. Another added a gate that removed a cluster of false matches on boilerplate symbols.

What it hasn't done

  • It has produced no confirmed vulnerability and $0 in bounty income. I built it to hunt bugs, and that goal hasn't paid.
  • It is 7 weeks old and has not run for a client. You would be an early customer.
  • It does not watch queued governance or oracle and parameter changes, and it does not know what has been reviewed. Those are pilot builds.
  • About a third of audit reports parse automatically. The rest need more work, which is why the register has a "can't tell" state.
  • The spend ledger is safe on one machine. I keep spending on a single host rather than assume otherwise.

I keep inspected facts, reported facts and hypotheses apart. You would want the same from anything triaging your alerts.
